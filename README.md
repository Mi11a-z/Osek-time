# Osek-time
сайт - сплетни Казахстана

Веб-приложение в стиле Threads / X (Twitter) для публикации отзывов и коротких постов. Приложение поддерживает **режим анонимной публикации**, позволяя пользователям выбирать, делиться мнением от своего имени или анонимно. В системе четыре уровня доступа: **гость, пользователь, модератор, администратор**. Проект разрабатывается в рамках 7-недельного учебного спринта на **Next.js** с настоящей базой данных и серверной проверкой прав.

## 🛠 Технологический стек

* **Фреймворк:** Next.js (App Router) + React

## 🔐 Роли пользователей и приоритет

Чем выше уровень, тем больше прав. Каждая следующая роль включает права предыдущей.

| Уровень | Роль | Описание |
|---|---|---|
| 0 | **Гость** | Не вошёл в систему. Читает ленту, не может писать, лайкать и жаловаться. |
| 1 | **Пользователь** | Создаёт посты (публично/анонимно),сохранять , лайкает, удаляет свои посты, жалуется на чужие, имеет личный кабинет. |
| 2 | **Модератор** | Всё, что пользователь, плюс: просмотр жалоб, скрытие/удаление чужих постов, временный бан. |
| 3 | **Администратор** | Всё, что модератор, плюс: назначение модераторов, перманентный бан, удаление аккаунтов, статистика. |

### Правило анонимности

Модератор и администратор **видят автора анонимного поста** (чтобы можно было блокировать за клевету и оскорбления). Обычные пользователи и гости автора не видят никогда. Благодаря серверу это реально обеспечивается: данные об авторе анонимного поста **не отправляются в браузер** тем, у кого нет прав (см. `lib/serializers.js`).

## 📋 Подробное описание функционала

### Гость
* Видит ленту всех нескрытых постов.
* У анонимных постов видит «Аноним», у обычных — имя автора.
* Видит количество лайков.
* При попытке лайкнуть, написать пост или пожаловаться получает предложение войти или зарегистрироваться.

### Регистрация и авторизация
* **Регистрация:** логин (уникальный, 3–20 символов), пароль (от 6 символов), повтор пароля. Новый аккаунт: роль `USER`, статус `ACTIVE`. Пароль сохраняется как `bcrypt`-хеш.
* **Вход:** логин и пароль. Забаненному вход блокируется с сообщением и сроком окончания бана.
* **Сессия:** подписанная `httpOnly`-cookie, сохраняется после перезагрузки.
* **Выход:** cookie удаляется, пользователь становится гостем.
* Понятные ошибки: «Неверный логин или пароль», «Логин уже занят».

### Пользователь
**Создание поста**
* Текстовое поле (до 500 символов, со счётчиком) и тумблер «Опубликовать анонимно».
* Пустые посты и посты из одних пробелов не принимаются (проверка на сервере).
* При анонимной публикации `isAnonymous = true`, на карточке «Аноним» и аватар-инкогнито.
* `authorId` сохраняется всегда: автор может удалить пост, модератор может реагировать на нарушения.

**Лента**
* Сортировка от новых к старым.
* Карточка: автор (или «Аноним»), дата, текст, лайк со счётчиком, «Пожаловаться», у своих постов «Удалить».
* Скрытые модератором посты в общей ленте не показываются.

**Лайки** — один лайк на пользователя на пост (составной ключ в БД), повторный клик снимает его, счётчик обновляется сразу.

**Удаление** — автор может удалить любой свой пост (в т.ч. анонимный) после подтверждения.

**Жалобы**
* Модальное окно с причиной: оскорбления, клевета, спам, личные данные, другое.
* На один пост один пользователь жалуется только один раз (уникальный индекс в БД).
* Жалоба попадает в очередь модератора.

**Личный кабинет**
* Имя, дата регистрации, роль.
* «Мои посты»: публичные и анонимные (анонимные помечены значком, видны только автору).
* Количество постов и полученных лайков.

### Модератор
* Раздел «Жалобы»: посты с жалобами, причина, количество, дата.
* Действия: **отклонить** жалобу; **скрыть пост**; **удалить пост**; **временно заблокировать автора** (1, 7 или 30 дней).
* Видит настоящего автора анонимного поста.
* Не может банить админов и других модераторов, не может менять роли.

### Администратор
* Всё, что умеет модератор.
* Раздел «Пользователи»: логин, роль, статус, дата регистрации.
* Действия: назначить/снять модератора, заблокировать навсегда, разблокировать, удалить аккаунт.
* Админ не может снять роль с самого себя (в системе всегда остаётся хотя бы один админ).
* Статистика: число пользователей, постов, анонимных постов, открытых жалоб.

### Правила доступа и безопасности
* Права проверяются **на сервере** при каждом действии (Server Actions / API) через единую функцию `can(user, action, target)`. Скрытие кнопок в интерфейсе — только удобство, а не защита.
* `middleware.js` перенаправляет неавторизованных и пользователей без нужной роли со страниц `/moderator`, `/admin`.
* Забаненный не может писать, лайкать и жаловаться, но может читать ленту. Временный бан снимается автоматически по истечении срока (проверка при каждом запросе).
* Данные об авторе анонимного поста не попадают в ответ сервера для обычных пользователей и гостей.
* Пароли хранятся только в виде хеша; секреты (`JWT_SECRET`, `DATABASE_URL`) лежат в `.env` и не попадают в Git.

### Нефункциональные требования
* Адаптивность: от 360 px до десктопа.
* Обновление интерфейса без полной перезагрузки (лайк, удаление, жалоба).
* Подтверждения для опасных действий (удаление, бан) и понятные сообщения об ошибках.
* Код разделён на слои: UI-компоненты, серверная логика, доступ к БД, проверка прав.

## 🗄 Структура данных (Prisma)

```prisma
enum Role   { USER MODERATOR ADMIN }
enum Status { ACTIVE BANNED }
enum ReportStatus { NEW RESOLVED }

model User {
  id           String   @id @default(cuid())
  username     String   @unique
  passwordHash String
  role         Role     @default(USER)
  status       Status   @default(ACTIVE)
  bannedUntil  DateTime?          // null + BANNED = перманентный бан
  createdAt    DateTime @default(now())
  posts        Post[]
  likes        Like[]
  reports      Report[]
}

model Post {
  id          String   @id @default(cuid())
  authorId    String
  author      User     @relation(fields: [authorId], references: [id])
  content     String
  isAnonymous Boolean  @default(false)
  isHidden    Boolean  @default(false)
  hiddenById  String?
  createdAt   DateTime @default(now())
  likes       Like[]
  reports     Report[]
}

model Like {
  userId String
  postId String
  user   User @relation(fields: [userId], references: [id])
  post   Post @relation(fields: [postId], references: [id], onDelete: Cascade)
  @@id([userId, postId])
}

model Report {
  id         String       @id @default(cuid())
  postId     String
  reporterId String
  reason     String
  status     ReportStatus @default(NEW)
  createdAt  DateTime     @default(now())
  post       Post @relation(fields: [postId], references: [id], onDelete: Cascade)
  reporter   User @relation(fields: [reporterId], references: [id])
  @@unique([postId, reporterId])
}
```

## 🧪 Чек-лист тестирования (неделя 7)

| Проверка | Ожидаемый результат |
|---|---|
| Гость пытается лайкнуть | Предложение войти |
| Пользователь пишет анонимный пост | В ленте «Аноним», в кабинете пост помечен как анонимный |
| Другой пользователь смотрит этот пост | Автор не виден |
| В ответе сервера (вкладка Network) для обычного пользователя | Нет `authorId` и имени автора анонимного поста |
| Пользователь открывает URL админки | Перенаправление на главную |
| Пользователь вызывает API модерации напрямую | Ответ 403 |
| Модератор скрывает пост | Пост пропадает из ленты |
| Модератор пытается назначить роль | Действие недоступно |
